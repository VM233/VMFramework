# Procedure transition and initializer source lifetimes

IProcedureManager.EnterProcedure, EnterProcedureImmediately and ExitProcedureImmediately return the actual accepted Task. Both queued and immediate APIs use the same ProcedureTransitionRequest producer; no EnterAsync adapter or consumer OnEnter TaskCompletionSource exists. Synchronous qualification failure admits no queue entry. Every caller must retain and observe that returned Task. IsLoading and current procedure publication are independent current facts, not evidence that another request completed.

The request captures its source and target identities before source work. ProcedureManager owns actual loading, FSM exit/entry and public callback phases. Completion publishes only after loading and active-request ownership retire. Native entry or entry-subscriber failure carries ProcedureTransitionException.Primary, the exact Phase and independent retirement failures. Inverse cleanup withdraws the acquired target before restoring the original live source. Owner destruction or a canceled owner lifetime retires acquired resources without reopening the source procedure. A canceled initialization token cannot skip already-acquired target cleanup.

RetireAsync publishes one original owner Task before cancellation, snapshots the actual queue and joins the active accepted source. Each queued request gets its own matched canceled product. The .NET Standard 2.1 token-preserving TrySetCanceled API publishes cancellation on that same Task; a second terminal publication throws at the request boundary. Cancellation-callback errors do not stop attempts to retire other requests, initializer sources or CTS subscriptions. Manager singleton withdrawal remains base-owned and runs in finally. Editor Play exit and beforeAssemblyReload request this actual owner retirement. These hooks do not claim arbitrary third-party forced reload can await a source after managed assemblies are forcibly discarded; controlled automation must join actual retirement before requesting reload.

InitializerManager captures the actions of one order and preserves each raw UniTask exactly once. It observes forced cancellation and then joins that same original source. Every action in the order really terminates before the order or manager Task is terminal, including non-cooperative sources released by their actual producer. Primary source errors, cancellation callback errors and late source errors remain original exception objects. Caller cancellation and timeout classification require the corresponding actual token; a foreign OperationCanceledException cannot become the caller's cancellation merely because that caller also canceled. Later orders never start after the current order fails.

The request source and Task remain owned until all final callback/state publication is complete. Automatic transitions observe their actual Task and consume only its matched canceled state. UI/session callers must observe the original request directly and separately own the resources that their transition adopted. No mutable latestTask, ready flag, fallback target, retry or duplicate request registry supplies terminal evidence.

Focused qualification uses the existing VMFramework.Editor.Tests.InitializerManagerTests fixture:ordered concurrency, duplicate registrations, sibling failure, caller cancellation, non-cooperative timeout, throwing cancellation callback, late source failure and foreign cancellation. The test initializer requires explicit action definitions and is installed through InitializerManager.Set; no automatically discoverable shadow IProcedure is added. The DD2 storage-owner entry-callback witness uses the real MainMenu/Client procedures and exact request phase, automatic save Task and rollback receipt; it is a separate native integration result.

Static cost is parameterized by actual source domains. One transition owns one request/Completion Task, at most one active loading task, and a queue snapshot of N original requests. Retirement visits each once after closing admission. One initialization order owns A preserved raw sources and A observation Tasks plus one WhenAll; no repeated await of an unpreserved UniTask or polling loop is added. Focused qualification uses N<=2 and A<=3; these are test inputs, not new runtime caps. The eight initializer cases create9 managed managers, at most3 declared actions in one fixture and zero GameItems, Scene objects, trace writers or production registrations. Actual timer9.1.20 physical-clock retirement remains unchanged.

The original ProcedureManager.cs script identity is retained. Loading, Query and NameList partial source/meta files are removed after their actual GUID reference census; query/Inspector/loading responsibilities belong to the single non-partial owner. Package metadata, exact deletion manifest, source hashes and focused test costs accompany the prepared source. Official compilation, code-policy, focused package tests and consumer native qualification are independent execution evidence.
