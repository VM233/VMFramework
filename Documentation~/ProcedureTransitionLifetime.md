# Procedure transition and initializer source lifetimes

IProcedureManager.EnterProcedure, EnterProcedureImmediately and ExitProcedureImmediately return the actual accepted Task. Both queued and immediate APIs use the same ProcedureTransitionRequest producer; no EnterAsync adapter or consumer OnEnter TaskCompletionSource exists. Synchronous qualification failure admits no queue entry. Every caller must retain and observe that returned Task. IsLoading and current procedure publication are independent current facts, not evidence that another request completed.

The request captures its source and target identities before source work. ProcedureManager owns actual loading, FSM exit/entry and public callback phases. Completion publishes only after loading and active-request ownership retire. Native entry or entry-subscriber failure carries ProcedureTransitionException.Primary, the exact Phase and independent retirement failures. Inverse cleanup withdraws the acquired target before restoring the original live source. Owner destruction or a canceled owner lifetime retires acquired resources without reopening the source procedure. A canceled initialization token cannot skip already-acquired target cleanup.

RetireAsync publishes one original owner Task before cancellation, snapshots the actual queue and joins the active accepted source. Each queued request gets its own matched canceled product. The .NET Standard 2.1 token-preserving TrySetCanceled API publishes cancellation on that same Task; a second terminal publication throws at the request boundary. Cancellation-callback errors do not stop attempts to retire other requests, initializer sources or CTS subscriptions. Manager singleton withdrawal remains base-owned and runs in finally. Editor Play exit and beforeAssemblyReload request this actual owner retirement. These hooks do not claim arbitrary third-party forced reload can await a source after managed assemblies are forcibly discarded; controlled automation must join actual retirement before requesting reload.

InitializerManager captures the actions of one order and invokes and awaits each raw UniTask exactly once. The action token links sibling, caller and timeout cancellation. A pending source remains owned until its actual producer terminates it; no external cancellation wait detaches that source. After the join, actual token checks govern success adoption. A late source failure remains primary, with independently requested forced cancellation recorded through its actual token boundary. Source exceptions are the objects actually received from the awaiter: a token-only cancellation producer cannot promise the identity of an injected exception. Caller cancellation and timeout classification require the corresponding actual token; a foreign OperationCanceledException cannot become the caller's cancellation merely because that caller also canceled. Every accepted action terminates before its order or manager becomes terminal, and later orders never start after failure.

The request source and Task remain owned until all final callback/state publication is complete. Automatic transitions observe their actual Task and consume only its matched canceled state. UI/session callers must observe the original request directly and separately own the resources that their transition adopted. No mutable latestTask, ready flag, fallback target, retry or duplicate request registry supplies terminal evidence.

Focused qualification uses InitializerManagerTests in the VMFramework.Editor.Tests assembly: ordered concurrency, duplicate registrations, sibling failure, caller cancellation, non-cooperative timeout, throwing cancellation callback, late source failure and foreign cancellation. The test initializer requires explicit action definitions and is installed through InitializerManager.Set; no automatically discoverable shadow IProcedure is added. Consumer procedure entry, automatic saves and inverse cleanup require separate native integration evidence.

Static cost is parameterized by actual source domains. One transition owns one request/Completion Task, at most one active loading task, and a queue snapshot of N original requests. Retirement visits each once after closing admission. One initialization order owns A raw sources and A execution products joined by one WhenAll; each accepted source is invoked and awaited once. The focused initializer cases create nine managers, declare fifteen actions, invoke fourteen sources and enter ten orders, with at most two pending sources at once. They add no GameItems, Scene objects, trace writers or production registrations. These are test inputs, not runtime caps.

The original ProcedureManager.cs script identity is retained. Query, Inspector and loading responsibilities belong to that single owner. Official compilation, code-policy, focused package tests and consumer native qualification provide independent evidence.

UI procedure authoring declares `UIPanelProcedureConfig.enteringPage` as one typed UI Toolkit panel reference. `UIPanelProcedureGeneralSetting.GetEnteringPageStrictly` returns that exact primary configuration; `OnEnterProcedure` opens it before the configured auxiliary panels. Move the primary page from the auxiliary list into this field and keep auxiliary overlays in the original list. Consumers use this explicit role when adopting a procedure's page; panel ordering, directory names and global panel-open notifications do not establish that role.

UI procedure publication owns its collection lifetimes. UIPanelManager keeps one HashSet per actually opened panel ID for the manager lifetime; these retained sets are owner allocations, not unreturned pool rentals. Procedure close publication borrows one snapshot list at a time and returns it in finally even if an actual panel close throws. This changes no panel traversal domain: at most G retained sets for G registered panel definitions (frozen consumer G1045, audited envelope2048), and the existing largest open-panel snapshot. The previous implementation already allocated the same sets when its pool was empty; the repair adds no live collection axis, history or native object. Snapshot finally adds one constant return on both success and failure. Pass for unchanged loop/collection bounds and paired ownership. Native open/reopen/close/failure and transition retirement remain the acceptance path.
